项目 1 的 RAG 改造方案遵循"最小改动、补齐缺口、形成闭环"三原则。做法是把 rag_search 作为第四个工具接入现有 Agent：文档放进 knowledge_base/ 目录，rag/build_kb.py 负责"切分（chunk=500, overlap=80）→ bge-m3 向量化 → Chroma 持久化"，tools/rag_tool.py 用 as_retriever(k=3) 实现检索并把来源拼进结果，最后在 agent.py 注册一行工具、在系统提示词里加一句"知识性问题优先检索"。评测侧用 15-25 条问答集测检索命中率、答案忠实度、答案准确率，并做"无 RAG 基线 / 加 RAG / 调参"对比实验，拿到真实数字回填 README 和简历。改造价值：三个项目原本全是 Agent，缺一个 RAG；补上后既能讲"做了 RAG"，又能讲"用项目 3 的评测体系量化了 RAG 效果"，这是普通 RAG 项目没有的差异化故事。需要提醒的是，方案里所有【X】占位数字、命中率与忠实度都必须真跑实验后填写，语料本身只提供可检索的知识，不提供虚构的结论。
